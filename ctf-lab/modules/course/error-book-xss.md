## 2026-08-18 · xs4 重打

- **卡点/偏差**：payload 里 `+document.cookie` 的 `+` 没编码，到服务器变成空格 → JS 语法错误 → 攻击静默失败。
- **根因**：URL 查询参数中 `+` 表示空格！要传真正的加号必须编码为 `%2B`。（关联 ch4 URL 编码：`+` 与 `%20` 都表示空格）
- **排错方法**：curl 看服务器回显——对比 payload 原文，发现 `+` 变成了空格。回显是排错的第一现场。
- **教训**：URL 里传 payload 特殊字符要编码：`<`→%3C `>`→%3E 空格→%20 `+`→%2B `'`→%27 `"`→%22 `#`→%23 `&`→%26

## 2026-08-18 · xs3 重打

- **卡点/偏差**：把 DOM 型认成反射型，答"反射型不经过服务器"——记反了。
- **根因**：三类型的"是否经过服务器"特征混淆。正确：反射型✅经过（URL 参数→服务器 echo）；存储型✅经过（提交→服务器存储→输出）；DOM 型❌不经过（# 后面是浏览器本地 fragment，服务器收不到）。
- **记忆锚点**：DOM 型 = 服务器日志查不到 payload（根本没发过去）。

## 2026-08-18 · xs2 重打

- **卡点/偏差**：alert 能弹窗，prompt/confirm 不弹。
- **根因**：Chrome 规定 `confirm()`/`prompt()` 必须由**用户手势**（点击等）触发，而 `<script>` 在页面加载时自动执行 = 无用户激活 → Chrome 静默忽略（confirm 返回 false / prompt 返回 null）。`alert()` 是例外，不需要用户激活。
- **推论**：XSS 验证首选 alert；换 confirm/prompt 主要是为了"绕过滤"（filter 拦 alert 字符串），但要注意触发时机——放 `<a href="javascript:...">` 或 onclick 里靠点击触发才稳。
- **关联**：这解释了为什么题目/教程默认用 alert(1)。
- **⚠️ 修正（2026-08-18 xs5 实测）**：用户 Firefox 环境下，`confirm(1)` 在 `<script>` 自动执行和 `onerror` 里**都能弹**。xs2 当时不弹的原因未确认（可能当时 payload/操作差异）。结论：不同浏览器对 confirm/prompt 的激活限制不一致，**以自己环境的实测为准**；CTF 里 alert 被过滤时优先试 confirm。

- **卡点/偏差**：费曼输出时把 `<script>` 说成"函数"。
- **根因**：HTML 标签 vs JS 函数的概念混淆——`<script>` 是 HTML 标签（代码区标记），`alert()` 才是 JS 函数。浏览器解析到 `<script>` 标签 → 内容当 JS 执行 → `alert(1)` 弹窗。
- **正确链路**：`?q=` 原样输出进 HTML → `<script>` 标签被浏览器解析 → 内容按 JS 执行 → 弹窗。
- **关联**：同族概念——`onerror` 也是 HTML 属性（不是函数），它"存"的是 JS 代码。
